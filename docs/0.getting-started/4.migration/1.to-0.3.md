# Migrate from 0.2 to 0.3

> Update code written for unsecure 0.2.x so it runs on 0.3: the one error class, the removed codec wrappers, stricter decoding, and the inputs that now throw.

0.3 is a breaking release, and two of its changes touch every module. The library now throws one error class, and it checks inputs it used to wave through. The codecs also lost their `*Encode` and `*Decode` wrappers and decode strictly by default. Work through the sections that name a function you call; anything not listed here behaves as it did.

## Before you start

Three things are worth sorting out before you bump the version:

- **Runtime**: Node.js 22.13 or later (24 or later on the 24 line).
- **Tests**: assertions on error messages or `instanceof TypeError` need rewriting; section 1 shows the replacement.
- **Codecs**: calls change name and behavior together, so update sections 2 and 3 in one pass.

## 1. Catch `UnsecureError` and branch on `code`

0.2 threw whatever was at hand: `Error`, `TypeError`, `RangeError`, `SyntaxError` or a Web Crypto `DOMException`. 0.3 always throws an [`UnsecureError`](/safety/errors) with a `code`, so your `catch` blocks change like this:

<!-- automd:region src="../../../examples/getting-started/migrate-errors.ts" -->

```ts [migrate-errors.ts]
import { UnsecureError } from "unsecure/errors";
import { base64Parse } from "unsecure/utils";

/** An uploaded avatar sent as base64, or `null` when the text isn't base64. */
export function readAvatar(text: string): Uint8Array | null {
  try {
    return base64Parse(text, { returnAs: "bytes" });
  } catch (error) {
    // 0.2: if (error instanceof SyntaxError) return null;
    if (error instanceof UnsecureError && error.code === "MALFORMED") return null;
    throw error;
  }
}
```

<!-- /automd -->

A Web Crypto refusal becomes `PLATFORM`, and invalid JSON in `safeJsonParse` becomes `MALFORMED`; both keep the original error in `cause`, so nothing gets lost. Several messages changed wording or gained the function name as a prefix, which is one more reason to match on `code` and never on text. A minor release can add a code, so keep a `default` branch in any `switch`.

## 2. Replace the codec wrappers

The `*Encode` and `*Decode` wrappers are gone, and each one has a direct replacement in `unsecure/utils`:

| 0.2                     | 0.3                                                         |
| ----------------------- | ----------------------------------------------------------- |
| `hexEncode(data)`       | `hexStringify(data)`                                        |
| `hexDecode(text)`       | `hexParse(text, { loose: true })`                           |
| `base64Encode(data)`    | `base64Stringify(data)`                                     |
| `base64Decode(text)`    | `base64Parse(text, { loose: true })`                        |
| `base64UrlEncode(data)` | `base64Stringify(data, { alphabet: "base64url" })`          |
| `base64UrlDecode(text)` | `base64Parse(text, { alphabet: "base64url", loose: true })` |
| `base32Encode(data)`    | `base32Stringify(data)`                                     |
| `base32Decode(text)`    | `base32Parse(text, { loose: true })`                        |

The old wrappers were forgiving, so `{ loose: true }` keeps your code doing what it did. Drop it once you know the text is canonical. Loose decoding accepts several spellings of the same bytes, and that's wrong for anything you compare as text or use as an identifier. `Hex`, `Base64` and `Base32` remain as objects holding the same two functions. [Codecs](/safety/codecs) documents both modes.

## 3. Expect strict decoding to refuse more

Strict `parse` is the default, and it accepts only canonical spellings of some bytes. Padded and unpadded text both count as canonical unless you pin `padding`:

- **Whitespace**: a space or newline is an invalid character. `"Zm 9v"` used to decode as base64.
- **Padding**: `=` must be complete or absent. `"Zm9vYg="` and `"Zm9vYmFy="` are refused. Set `padding: true` or `padding: false` to require one spelling.
- **Trailing bits**: `"Zh=="` and `"MZXW7==="` set bits past the last byte and are refused.
- **Case in base32**: the `base32` and `base32hex` alphabets accept uppercase only. Crockford stays case-insensitive.
- **Byte input**: a `Uint8Array` is read as encoded text one byte per character, so a UTF-8 byte order mark is three invalid characters.
- **Text output**: decoded bytes that aren't valid UTF-8 throw `MALFORMED` when you ask for a string. Pass `returnAs: "bytes"` for binary data.

Loose decoding changed too: `hexParse` now skips characters it can't read instead of giving up at the first one. `"66 6f 6f"` used to decode to one byte and now decodes to `foo`. A custom base32 `alphabet` must be 32 distinct ASCII characters without `=` or whitespace, or it throws `OUT_OF_RANGE`. [Codecs](/safety/codecs#when-it-fails) lists each refusal.

## 4. Check what now throws or changed result

These are the inputs that 0.2 let through quietly or rejected with a native error:

- **[`secureCompare`](/generate/secrets/compare)**: a `null` or plain-array `received` returns `false`; an `expected` that is neither text, bytes nor `undefined` throws `INVALID_TYPE`. Both arguments accept any `BytesSource`.
- **[`hash`](/crypto/hashing/hash), [`hmac`](/crypto/hashing/hmac), [`hkdf`](/crypto/key-derivation)**: data that isn't text or bytes throws `INVALID_TYPE`. An empty HMAC secret throws `OUT_OF_RANGE`.
- **[`hmacVerify`](/crypto/hashing/hmac)**: a string signature is decoded with the codec named by `returnAs`, hex by default, whatever the type of `data`. Uppercase hex now verifies.
- **[`hotpVerify`](/crypto/otp)**: an `undefined` counter throws. It used to accept the code for counter 0.
- **[OTP options](/crypto/otp)**: `digits` outside 6 to 8, `generateOTPSecret(0)`, `period: null`, `time: null`, an empty secret and `issuer: ""` throw. Omit an option to take its default.
- **[`otpauthURI`](/crypto/otp)**: values are percent-encoded, so `My App` becomes `My%20App`, not `My+App`.
- **[`secureGenerate`](/generate/secrets/generate)**: `length` must be an integer of at least 1, an invalid `Date` timestamp throws, and a character in two selected sets throws `OUT_OF_RANGE`. `length` counts code points, so output never splits an emoji.
- **[`sanitizeObjectCopy`](/safety/sanitize)**: copies plain objects and arrays only. A `Date`, `Map`, `Set`, typed array or class instance throws `INVALID_TYPE` unless its constructor is in `allowlist`; listed values pass by reference. Accessors are skipped.
- **[`sanitizeObject`](/safety/sanitize)**: a dangerous key on a frozen or sealed object throws `FROZEN`. All three sanitizers handle any nesting depth.
- **[`randomJitter`](/generate/random)**: a fractional or `null` bound throws `OUT_OF_RANGE`. Only `undefined` takes a default, so `randomJitter(undefined, 50)` waits up to 50 ms.
- **[`secureRandomBytes`](/generate/random)**: a length above `2**31 - 1` throws `OUT_OF_RANGE`.

One change needs no edit but is good to know. `hotpVerify` and `totpVerify` now check the whole window on every call. Their `delta` reports the nearest match rather than the first one checked.

## 5. Adopt what 0.3 adds

Nothing here forces an edit, but each one can replace code you may have written yourself:

- [`unsecure/argon2`](/crypto/password-hashing) for password hashing, and [`unsecure/errors`](/safety/errors) for the error class
- [`totpVerify`](/crypto/otp) option `lastAccepted`, which refuses a replayed code; both verify results report the matching `step` or `counter`
- [`importHmacKey`](/crypto/hashing/hmac) and [`importHkdfKey`](/crypto/key-derivation), and a `CryptoKey` accepted as the secret of `hmac`, `hmacVerify`, `hkdf` and the four OTP functions
- Algorithm names matched case-insensitively, so `"sha-256"` works
- [`unsecure/odds`](/generate/odds) for fair-feeling draws
