# Generate tokens and secrets

> Make API tokens, invite codes and temporary passwords that nobody can guess, from the characters you choose.

`secureGenerate` makes a string nobody can guess. You pick the length and the characters it may use, and every character comes from the platform's secure random generator. Use it for anything that opens a door: a bearer token, an invite code, a password reset code, a first password. If you're wondering why `Math.random()` won't do, [Concepts](/getting-started/concepts#where-randomness-comes-from) has the short answer.

## Before you start

- It runs on Node.js 22.13 or later (24 or later on the 24 line), Bun, Deno and browsers. Every call is synchronous.
- Strength comes from length and the size of the character set. 32 letters and digits give about 190 [bits](/getting-started/concepts#bits-and-what-they-measure), and 128 bits is already out of reach for brute force.
- Store a token you issue as a digest and show it to its owner once. The [API tokens recipe](/examples/api-tokens) walks through that flow.
- It doesn't judge a string someone else picked. For that, see [Check a secret's entropy](/generate/secrets/entropy).

## Make a token for each kind of reader

People and programs read tokens differently. Each function below suits one reader: a program, a person typing from a printout, someone signing in for the first time.

<!-- automd:region src="../../../examples/generate/random-tokens.ts" -->

```ts [random-tokens.ts]
/** A bearer token for an API client: 32 letters and digits, about 190 bits. */
export function newApiToken(): string {
  return secureGenerate({ length: 32, specials: false });
}

/**
 * An invite code people read off a printout. The sets leave out look-alikes
 * (0 and O, 1 and I and L), and every code holds a letter and a digit.
 */
export function newInviteCode(): string {
  return secureGenerate({
    length: 10,
    uppercase: "ABCDEFGHJKMNPQRSTUVWXYZ",
    lowercase: false,
    numbers: "23456789",
    specials: false,
  });
}

/** A first password for an account an admin creates, shown once. */
export function newTemporaryPassword(): string {
  return secureGenerate({ length: 20 });
}
```

<!-- /automd -->

The options behave the same way in all three:

- **Character sets**: all four sets, `uppercase`, `lowercase`, `numbers` and `specials`, are on unless you say otherwise. Pass `false` to drop a set, or a string to use your own characters instead. Drop `specials` for anything that goes into a URL, a header or a shell command, where symbols need escaping.
- **One from each set**: every set you leave on puts at least one character in the result. So the temporary password always has an uppercase letter, a lowercase letter, a digit and a symbol. That promise needs room: with `length` below the number of sets, it's a draw which sets make it in.
- **No repeats**: list a character twice, in one set or across two, and it would come up twice as often as the others. Rather than hand you that lopsided draw, `secureGenerate` throws.
- **Code points**: `length` counts Unicode code points, the numbers Unicode gives each character. Your sets can hold characters beyond ASCII, and the result never cuts one in half. An emoji made of several code points, such as a flag, counts as several.

## When it fails

Everything that can go wrong here is a setup mistake. It throws an [`UnsecureError`](/safety/errors), so it shows up the first time the code runs:

| Situation | What happens |
| --- | --- |
| `length` is `0`, negative, fractional or `NaN` | Throws `OUT_OF_RANGE`. |
| Every set is `false` or an empty string | Throws `OUT_OF_RANGE`. |
| A character appears twice, within one set or across two | Throws `OUT_OF_RANGE`, naming the character. |
| `length` leaves no room after the timestamp prefix, such as `length: 8` | Throws `OUT_OF_RANGE`. |
| `timestamp` is an invalid `Date` | Throws `OUT_OF_RANGE`. |
| `timestamp` is a string or a nonzero number | Throws `INVALID_TYPE`. Wrap it in `new Date()` first. |
| `timestamp` is `0`, `""` or `false` | No prefix and no error: these read as no timestamp at all. |

## Options

`secureGenerate(options)` takes a single object, and you can leave out any field:

| Option      | Default | Notes                                                                    |
| ----------- | ------- | ------------------------------------------------------------------------ |
| `length`    | `16`    | Characters in the result, an integer of at least 1.                      |
| `uppercase` | `true`  | `A` to `Z`. `false` or `""` turns it off; any other string replaces it.  |
| `lowercase` | `true`  | `a` to `z`.                                                              |
| `numbers`   | `true`  | `0` to `9`.                                                              |
| `specials`  | `true`  | The 28 characters `!@#$%^&*()_+{}:<>?\|[];,./~-=`.                       |
| `timestamp` | none    | `true` for now, or a `Date`. See the timestamp note under Going further. |

## Going further

A few more things for when you size tokens yourself, want them to sort, or need a neighboring tool:

- **Sizing a token**: each random character is worth log2 of the set size in bits, so multiply that by the number of random characters. Letters and digits give 5.95 bits a character, the four default sets together 6.49.
- **Sortable tokens**: `timestamp: true`, or a `Date`, writes the time at the front of the token in base 36, so sorting the tokens sorts them by age. The prefix is 8 characters for any date between 1972 and 2059 and counts inside `length`. It's not secret, though: anyone holding the token reads the time back with `parseInt(token.slice(0, 8), 36)`, and someone who knows roughly when you made it can guess it. Count only the random characters when you size a timestamped token.
- **Raw key material**: when the secret is bytes for a key rather than text a person will handle, `secureRandomBytes` from [Draw random numbers](/generate/random) is the better fit.
- **Identifiers**: a string that names a record but doesn't open anything is an identifier, and a [UUID](/generate/uuid) is the tool for that.
- **Checking a submitted token**: compare it with [`secureCompare`](/generate/secrets/compare), or look it up by its digest.
