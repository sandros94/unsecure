# Recipes

> Whole tasks rather than single functions: what to call, in what order, and what to store between calls.

Each recipe is one whole job, written the way you'd ship it, with what goes wrong sitting right next to the code. The topic pages explain one function at a time; here you see them working together. Password storage and untrusted JSON have full walkthroughs on their own pages: [Store passwords](/crypto/password-hashing) and [Parse untrusted JSON](/safety/sanitize).

::card-group
::card{title="Verify a webhook" icon="i-lucide-webhook" to="/examples/webhook-verification"}
Check the provider's signature over the raw body, refuse stale deliveries, and answer every refusal with the same 401.
::
::card{title="Add two-factor login" icon="i-lucide-shield-user" to="/examples/two-factor-auth"}
Password, then authenticator code, each code accepted once, plus single-use recovery codes.
::
::card{title="Issue API tokens" icon="i-lucide-key" to="/examples/api-tokens"}
Generate a token, store only its digest, and find the row by that digest.
::
::card{title="Derive keys from one secret" icon="i-lucide-git-branch" to="/examples/key-derivation"}
One root secret, one labeled key per purpose, imported once at start-up.
::
::card{title="Use unsecure from a CDN" icon="i-lucide-globe" to="/examples/cdn-import"}
A plain HTML page that loads one module from esm.sh, pinned to a version.
::
